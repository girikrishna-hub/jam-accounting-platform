# Platform feedback (internal)

Gaps found while building this app, for the runtimes' owner to decide on. Runtime changes are made only by the owner. Until then the app handles each one itself, without copying or changing runtime code.

| # | Runtime | Finding | Effect | Workaround in this app |
| --- | --- | --- | --- | --- |
| PF-1 | cowr-react 1.0.0 | A failed action sets the workspace's failure state, and the whole workspace is replaced by a one-line error page. | A rejected import file would hide the workspace instead of showing its line errors. | **Resolved in cowr-react 1.1.0:** action failures show inline and the workspace stays; `onInvokeAction` returns the result. Panels now use it with `{ showFailure: false }`. |
| PF-2 | cowr-react 1.0.0 | The generic action bar invokes actions with no input. | Actions that need a file or a form cannot run from it. | **Resolved in cowr-runtime/cowr-react 1.1.0:** actions are registered `invocation: 'PANEL'` and the bar is off (`showActionBar={false}`); the CSS is gone. |
| PF-3 | cowr-react 1.0.0 | The header always shows the raw object ID. | Accountants see internal IDs such as `acc_led_…_1`. | **Resolved in 1.1.0:** object types set `presentation.showObjectId: false`; the CSS is gone. |
| PF-4 | cowr-runtime 1.0.0 | Access decision freshness is checked against the browser clock, but decisions come from the server. | Clock skew between browser and server could make every decision stale. | **Resolved in cowr-runtime 1.1.0:** the server stamps decisions and the browser runtime uses `decisionTiming: 'RECEIPT'`, so clock skew does not matter (checked with the browser clock an hour ahead). |
| PF-5 | bookkeeping-runtime 1.1.1 | Journal lines have no party or matter dimension. | Receivables, payables and clients'-money ledgers need their own sub-ledgers (Slices 3 and 1b). | Planned as application sub-ledgers. |
| PF-6 | financial-statements-runtime 1.0.1 | No cash flow statement. | Needed in Slice 5. | Planned as an application calculation. |
| PF-7 | bookkeeping-runtime 1.1.1 | One currency per ledger. | USD accounts are held at JMD equivalents. | Planned: store foreign amount and rate on app records. |
| PF-8 | identity-runtime, auth-runtime, session-runtime, iar-rbac-runtime, authorization-runtime 1.1.0 | The PostgreSQL adapters (`PgIdentityStore`, `PgCredentialStore`, `PgLockoutCache`, `PgSessionStore`, `PgRoleStore`, `PgPermissionStore`, `PgAuthorizationPolicyStore`) need `iar_*` tables, but no package publishes the schema or a `migrate()` (Bookkeeping does). | The runtimes' own storage cannot be used, so identities, credentials and sessions stay in app tables. | **Resolved upstream in iar-schema 1.0.0** (`migrate()` for all `iar_*` tables). The app still uses its own user and session tables; moving to the runtimes' Pg stores is a separate, optional change. |
| PF-9 | iar-rbac-runtime 1.1.0 | An assigned role with no Role definition throws `MissingReference` rather than returning a decision. | A caller must catch it to fail closed. | **Resolved in authorization-runtime 1.2.0:** the runtime returns an audited DENY. App now on 1.2.0; it still registers its roles and keeps the catch as defence in depth. |
| PF-10 | bookkeeping-runtime 1.1.1 | No query lists a ledger's journals (drafts or posted); `GetPostedLines` returns lines, not entries, and never drafts. | The app keeps a journal register (`app.journals`) for lists, status and the approval trail. | **Resolved in bookkeeping-runtime 1.2.0 (`ListEntries`).** The app uses it to register entries it did not create (such as the opening journal). The register stays for what the runtime does not track: approval status and who prepared, approved and posted each journal. |
| PF-11 | bookkeeping-runtime 1.1.1 | `EntryView` has no version or revision. | The app cannot tell from the entry alone that a draft changed after approval. | **Resolved in bookkeeping-runtime 1.2.0 (entry version, `expectedVersion`).** Approval records the entry version; posting passes it and the runtime refuses any other version in its own transaction. The app's fingerprint is gone (migration 005). |
| PF-12 | identity-contracts 1.2.0 (and every identity runtime that depends on it) | Depends on Zod 3.x, affected by GHSA-mrhx-c7xc-m3w5 (memory exhaustion validating oversized constrained collections; fixed only in Zod 4.6.6+). `npm audit` reports 11 high findings, all from this one advisory. | Cannot be fixed in the app: the runtimes bring their own Zod 3. | The app's own validation uses Zod 4.6.6+; request bodies are capped at 3 MB and journal lines at 200, which limits exposure. **Resolved in identity-contracts 1.3.0 (Zod 4).** App now on 1.3.0; `npm audit` reports 0 vulnerabilities. |
